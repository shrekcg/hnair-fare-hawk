# 消息通知渠道调研（个人可配置版）

> 用途：自研监控系统的消息通知。**只保留个人用户（无企业认证/执照）可独立配置的渠道**。企业认证类（短信签名、电话外呼、企微/飞书认证后权益等）不现实、不收录。
> 目标读者是后续 session：读这份文档就能快速选型、知道怎么配、有哪些能力，然后直接实现。

---

## 一、结论速览

| 渠道 | 接收端 | 个人门槛 | 强度 | 用途 |
|---|---|---|---|---|
| **企业微信自建应用 + 微信插件** | 微信 App | 免费注册（手机号即可，无需执照） | ⭐⭐⭐ 微信红点+声音，独立会话不折叠 | 微信侧主推 |
| **飞书自建应用 + urgent_app 加急** | 飞书 App | 免费建团队（手机号即可） | ⭐⭐⭐ 桌面弹窗+红色加急标识 | 主推，含单聊/卡片 |
| **钉钉群机器人 webhook** | 钉钉 App | 免费注册（手机号即可） | ⭐⭐ 群消息+可@所有人 | 备选/已有钉钉群 |
| **Bark（iOS）** | iPhone | 免费开源，装 App 即用 | ⭐⭐⭐ APNs 原生推送，可设"时效性通知" | iOS 端第一选择 |
| **ntfy / PushDeer（安卓类 Bark）** | Android（也支持 iOS/桌面） | 免费开源/免费，装 App 即用 | ⭐⭐⭐ 原生通知，可设紧急级别 | 安卓端第一选择 |

**推荐组合（个人 0 元）：**
- **iOS 用户**：Bark（最简单、最显性）或飞书（要办公协同时）。
- **微信用户**：企业微信+微信插件（把告警推进微信）。
- **安卓用户**：ntfy（自托管可加紧急音）或飞书/钉钉。
- **要闭环/要别人也能接的自己监控**：飞书自建应用最完整（单聊+卡片+加急+已读回执），钉钉机器人最零成本（一个 webhook POST）。

统一封装：`notify(level, title, content)`，支持多通道路由：info→群机器人；warning→机器人+@/高优；critical→Bark/ntfy 紧急通知 + 飞书加急。

## 二、企业微信自建应用 + 「微信插件」（微信侧主推）

### 能力
- 给企业内成员/部门发**应用消息**（文本/图片/语音/文件/图文/视频，文字 600 字）。
- 成员用微信**扫码关注「微信插件」**（原企业号，注册企微后自动开通，每个企业一个）后，消息**直接推到微信**：聊天列表中「企业微信」独立会话，带红点+声音，不折叠——比公众号服务通知显性。
- 另有**群机器人 webhook**：群里添加机器人拿 URL，POST JSON 即推送，可 @所有人。

### 个人怎么配（免费，无需执照）
1. 官网/APP 免费注册企业微信：填企业名称（可自拟）、行业、员工规模 + 管理员手机号/微信扫码。不需要营业执照。（「个人组建团队」入口更简单，但**团队模式不能登录管理后台**，API 场景请用正常注册企业）
2. 管理后台 → 应用管理 → 自建 → 创建自建应用 → 拿 `AgentId` + `Secret`；成员管理里加自己/家人为成员。
3. 成员在微信扫「我的企业 → 微信插件」二维码关注插件（二维码 7 天有效）。
4. 调用：WebAPI 先拿 access_token，再 `POST /cgi-bin/message/send` 发应用消息。

### 未认证有什么限制（官方原文核实：19405/20385）
- **未认证也能用上面整条链路**，个人自用无感；发消息频率 = 人数上限(1000) × 200 人次/天，充足。
- 仅有的硬限制（个人用不到）：成员规模上限 100 人、通讯录 1000 人、外部联系人和对外拉群 100 人、企业简称无「已认证」标识、部分接口（如客户联系）受限。
- 认证=企业主体付费（300 元/次+年审），**个人不需要**，本方案完全绕过。
- 微信插件接收消息条件：插件右上角「设置→接收应用消息」开启、应用未停用、全员群 ≤2000 人。

## 三、飞书（能力最全，推荐主通道）

### 3.1 自建应用（个人可免费建团队）
- 注册飞书 → 创建「团队」（个人免费）→ 开放平台 open.feishu.cn 创建**自建应用** → 开机器人能力 → 拿 `App ID/App Secret`。
- 能力：单聊/群聊发消息（文本/富文本/交互卡片，卡片可带按钮回调做确认闭环）、已读回执、**加急**。

### 3.2 加急（个人免费项）——已从官方 SDK+帮助中心核实
| API | 效果 | 额度 |
|---|---|---|
| `PATCH /im/v1/messages/:id/urgent_app` | **应用内加急**：桌面=系统弹窗+飞书右侧红色加急；移动=红色加急标识→弹窗 | **免费、无额度** ✅ 个人可用 |
| `urgent_sms` / `urgent_phone` | 短信/电话加急 | 免费版未认证 0 次/月（**个人拿不到**）→不推荐 |
- 加急只能作用于**本应用自己发的消息**：先发消息拿 message_id → 再调加急接口传 `user_id_list`。
- 前提：应用开了机器人能力且在会话中；用户未读加急上限 200 条；加急不可取消；美国/新加坡不支持短信电话触达。
- **对个人用户的意义**：免费版+不认证就能做「应用内强提醒」，是飞书最强免费项。

### 3.3 群自定义机器人（零成本备用）
- 群里 → 设置 → 群机器人 → 自定义机器人 → webhook URL（可加签名校验，个人场景可不开）。
- `POST` JSON（text/富文本/卡片）即推送，可 @所有人；无加急接口。适合告警群/不装 App 的场景。

## 四、钉钉（最零成本，备选）

### 能力
- **群自定义机器人 webhook**：钉钉群 → 机器人 → 自定义机器人 → 复制 webhook → `POST` JSON，可 @所有人、消息类型 text/markdown/link/ActionCard。
- 免费、秒级；可选加签/关键词/IP 白名单安全设置（个人场景关键词最简单，比如设「监控」）。

### 个人怎么配
钉钉个人免费注册（手机号）→ 建个群（拉自己小号或开个单人群）→ 添加自定义机器人 → 拿 webhook → POST。

### 限制（官方口径）
- 机器人只能在群内发消息，无单聊、无加急 API（C 端的强提醒「电话 ding」不是 API 能力）。
- 没有类似飞书 urgent 的全局强提醒；适合告警群、适合已有钉钉组织。

## 五、iOS：Bark（APNs 原生推送，最显性的个人方案）

### 能力
- 开源免费 iOS App（GitHub Finb/Bark，MIT）：一个 HTTP 请求推 APNs 到 iPhone，**通知栏+声音+角标**。
- URL 即调用：`https://api.day.app/<device_key>/标题/内容`，或 POST JSON。
- 支持：自定义声音、分组、加密、历史记录、**时效性通知**（critical alert，锁屏响铃，可通过快捷指令/安装描述文件开启）、自建服务器（组件不依赖第三方）。
- 多端可用：iPhone/iPad/Mac（App Store 搜 Bark；Mac 端接同一 device key）。

### 怎么配
1. App Store 装 Bark → 打开即生成自己的 device key（形如 `xxxxxxxxxxxx`）。
2. 你的服务器把 device key 存起来 → 发通知：`curl https://api.day.app/<key>/告警标题/内容?group=监控`。
3. 高级：App 内开「时效性通知」并安装描述文件后，可带 `?level=timeSensitive` 触发锁屏强提醒。

## 六、安卓（及跨平台）类 Bark 应用

> 结论：**安卓第一选择 = ntfy**（最接近 Bark 体验）；要自托管/不依赖公网 = Gotify；国内轻量 = PushDeer。三者均免费/开源、个人可独立部署或直接用公共服务。

### 6.1 ntfy（最推荐，类似 Bark 的跨平台版）
- GitHub binwiederhier/ntfy，Apache-2.0，**社区非常活跃**（~34k star）。
- 能力：`PUT/POST https://ntfy.sh/<topic>` 即推送；安卓/iOS/Web/桌面客户端都有；**原生通知 + 可设紧急级别/自定义声音/操作按钮/定时延迟**。
- 个人用法：装 App → 订阅一个 topic（类似 Bark 的 device key）→ 服务器 POST 过去手机就响；也可自托管（有官方 docker，完全可控）。
- 教程化接口：`curl -d "监控告警：CPU 100%" ntfy.sh/my_topic`。

### 6.2 PushDeer（国内生态，扫码即用）
- 开源（easychen/pushdeer），支持 **iOS 14+ / 安卓 / Mac / 快应用**。
- 能力：iOS 走 APNs、安卓走厂商推送，扫码绑定即可；支持文本/图片/Markdown，可自托管。
- 国内访问友好（不依赖 Google 服务），适合给家属/轻量用户装。

### 6.3 Gotify（自托管，纯私有）
- GitHub gotify/server + gotify/android，开源（MIT），活跃维护（~16k star）。
- 能力：自建服务端（单二进制/docker）+ 安卓 App，WebSocket 实时推送；全私有无第三方。
- 适合：你已经有一台服务器、不想走任何公共推送服务；App 端体验略朴素。

### 6.4 对比
| | ntfy | PushDeer | Gotify |
|---|---|---|---|
| 是否需要自建 | 可公共(ntfy.sh)/可自建 | 可公共/可自建 | **必须自建** |
| 安卓厂商推送 | 自带前台/兼容 | 厂商通道 | 自带连接 |
| 紧急通知级别 | ✅ | 部分 | ✅（优先级） |
| 上手难度 | 最低 | 低 | 中（要装服务端） |

## 七、落地建议（直接照做）

1. **实现一个 `notify(level, title, content)` 多通道接口**：配置化（config.json）开关各渠道，默认全开。
2. **主通道**：飞书自建应用（单聊+卡片+urgent_app 加急）；**微信侧**：企微自建应用+微信插件；**手机端**：iOS 装 Bark、安卓装 ntfy。
3. 级别路由：info→群机器人(钉钉/飞书 webhook)；warning→机器人+@/高优；critical→Bark/ntfy 紧急通知 + 飞书 urgent_app。
4. 通用纪律：同一告警去重、限频（如 5 分钟一条）、静默时段可配置。
5. **给第三方个人用户接入时**：让他们各自免费注册对应 App（企微/飞书/钉钉/Bark/ntfy），把 device key / webhook / app_id+secret 交给你存配置——都是个人即可完成的动作，无企业认证环节。
