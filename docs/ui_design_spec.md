# 海航监控控制台 · UI 设计规范（v1）

> 服务对象：React + Vite 重写后的控制台前端（替代 Streamlit app.py）。
> 定位：一个「本机常驻的机票低价监控告警工具」的控制面板。用户每天打开它 1–3 次：确认监控在跑、看看任务有没有命中、偶尔改配置。
> 设计目标：**克制、可靠、信息密度高但不杂乱**——像 Linear / Vercel 的 dashboard，而不是消费级 App。

---

## 一、设计原则

1. **状态先行**：打开页面第一眼就能回答「监控在不在跑、有没有命中低价」。一切装饰退后。
2. **一屏一动作**：每个页面只有一个主任务（增删任务 / 管理票据 / 看历史），主按钮永远只有一个。
3. **凭证默认隐藏**：SendKey、cURL 这类敏感内容默认掩码展示，展开才见明文；这是工具类产品的安全感来源。
4. **少即是多**：删除教程长文案、部署入口、演示痕迹；让留下的每个控件都有明确目的。

### 2.2 字体栈

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
  "Hiragino Sans GB", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif;
```

- 中文优先 PingFang SC / 微软雅黑，数字与字母跟随系统无衬线；
- 代码与 cURL 文本用等宽：`ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`；
- 字号 scale：`12 / 13 / 14 / 16 / 20 / 24 / 32`（px）。正文 14，卡片标题 16，页面标题 24。

### 2.3 圆角 / 阴影 / 间距

- 圆角：卡片 `12px`，按钮/输入框 `8px`，徽章 `999px`。
- 阴影：卡片常态 `0 1px 2px rgba(16,24,40,0.06)`；悬浮 `0 4px 12px rgba(16,24,40,0.10)`；弹层 `0 12px 32px rgba(16,24,40,0.16)`。
- 间距 scale：`4 / 8 / 12 / 16 / 24 / 32 / 48`。页面内容区左右 padding 24，卡片内 padding 20。
- 内容区最大宽度 `1200px`，居中。

## 三、布局

### 3.1 整体骨架（不用侧边栏）

```
┌────────────────────────────────────────────────────────────┐
│ 顶部导航（64px）  [● 监控运行中|已停止]  [添加任务]          │
├────────────────────────────────────────────────────────────┤
│  页面 Tabs:  总览 | 任务 | 票据管理 | 设置                     │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 内容区（页面级内容）                                   │   │
│  └─────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────┘
```

- **顶部导航**：左侧 logo「海航监控」+ 全局监控状态指示灯（绿=运行中 / 灰=已停止，点击可直接全局启停）；右侧放「添加任务」主按钮（跨页面的最高频动作）。
- **二级 Tabs**：总览 / 任务 / 票据管理 / 设置。四个 Tab 平级，无嵌套侧边栏。
- **总览为默认落地页**：打开就是状态卡片 + 统计 + 最近命中，满足「状态先行」。

### 3.2 页面层级与路由

| 路由 | 页面 | 内容 |
|---|---|---|
| `/` | 总览 | 状态卡、统计卡（任务数/命中数/今日查询）、最近低价命中列表、快捷入口（去任务/去票据） |
| `/tasks` | 任务 | 添加任务表单 + 任务卡片网格（每任务带状态与价格趋势） |
| `/tickets` | 票据管理 | PLUS / 普通两张票据卡片（粘贴、校验、状态） |
| `/settings` | 设置 | 微信推送（SendKey）、监控时段、高级设置（代理、签名刷新） |
| `/history` | 历史 | 价格历史表（最近 50 条）+ 运行日志 |（可并入总览/设置，见 5.8）

### 3.3 卡片区块规则

- 每张卡片：白底、12px 圆角、细边框；标题区左对齐 16px semibold + 右侧放该区块主操作（如「+ 添加」）。
- 卡片间间距 16px；同页卡片不超过 4 张，避免滚动过长。
- 空状态必须给「下一步指引」，不给干巴巴的「暂无数据」。

## 四、组件规范

### 4.1 按钮

| 类型 | 样式 | 用途 |
|---|---|---|
| 主按钮 Primary | 蓝色实底白字 | 每页唯一主动作（保存、添加、启动） |
| 次按钮 Secondary | 白底细边框 | 次级动作（刷新、取消、预览） |
| 危险按钮 Danger | 红字或红底（带确认弹窗） | 删除任务、删除票据 |
| 文本按钮 Text | 无边框蓝色文字 | 折叠展开、跳转 |
| 图标按钮 Icon | 32×32 圆形 hover 底 | 表格行内操作（启停、删除、复制） |

规则：按钮高度 36px 统一；主按钮每页最多一个；危险操作必须二次确认（inline confirm 或弹窗）。

### 4.2 输入与选择

- 文本输入：高度 36px，`--color-border-strong` 描边，聚焦蓝色 2px ring（`box-shadow: 0 0 0 3px rgba(22,119,255,.15)`）。
- 城市输入：文本框 + 联想下拉（输入中文→提示三字码，选中即填码），候选最多 8 条，无匹配时允许直接输入三字码。
- 日期选择：原生 `input[type=date]` 即可（无需日历组件），中文 locale。
- 下拉 Select：监控时段用两组时间选择；票价类型用 Segmented Control（PLUS专享 | 普通票价）。
- 开关 Switch：启停任务、签名刷新等布尔项，右侧显示当前文案（如「已开启 · 刷新 stime 并重签」）。

### 4.3 表格

- 价格历史表：表头 12px 灰字，行高 44px，hover 浅底；数字右对齐（价格列）；「低价命中」行整行浅粉底（`--color-low-price` 8% 透明度）并带徽章。
- 日志：等宽字体 12px，行间无边框，超出滚动；错误行红字，告警行黄字。
- 移动端（窄屏）表格转卡片列表。

### 4.4 状态徽章 Badge

| 徽章 | 色 | 含义 |
|---|---|---|
| `运行中` | 绿点+绿字 | 监控/任务正常轮询 |
| `已停止` | 灰点+灰字 | 手动停止 |
| `低价命中` | 粉底粉字 | 触发阈值并已推送 |
| `无票/空结果` | 灰字 | 本轮无结果 |
| `错误` | 红字 | 验签失败/凭证失效/网络错误 |
| `待配置` | 黄字 | 票据缺失、参数待填 |

徽章统一：12px、圆角 999、`-soft` 底 + 深色字、前置 6px 圆点。

### 4.5 空状态

统一结构：`32px 图标 + 一行标题 + 一行说明 + 一个操作按钮`。例如任务为空：「还没有监控任务 / 添加后 daemon 会按你设定的阈值轮询 / [添加第一个任务]」。

### 4.6 Toast / 告警

- 成功/失败/信息：右上角 Toast，3 秒自动消失，成功绿、失败红、信息蓝。
- 持久告警（如「凭证已失效，daemon 已退避」）：页面顶部横幅 Banner，带关闭按钮但可重复出现。

## 五、关键页面 / 模块设计

### 5.1 总览（默认页）

```
┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐
│ 监控状态    │ │ 监控任务    │ │ 今日命中    │ │ 今日查询    │
│ ● 运行中    │ │    3       │ │    2       │ │   287      │
│ [停止监控]  │ │ [管理]      │ │ [看历史]    │ │ 自适应频率  │
└────────────┘ └────────────┘ └────────────┘ └────────────┘
最近低价命中（最多 5 条）：
  JD5290 深圳→杭州 09-17   ¥199   含税¥319   10 分钟前  [查看任务]
```

- 四张统计卡一行，数值 32px；监控状态卡的主按钮「停止/启动监控」是全局最高频动作。
- 下方「最近命中」列表：若连续无命中超过 24h，显示柔和提示「近 24 小时无低价命中，监控继续运行中」。
- 底部快捷入口：票据缺失时显示黄色横幅「PLUS 票据未配置，PLUS 任务将无法查询 → 去配置」。

### 5.2 任务页

**添加任务（顶部表单卡）**
一行式表单：`出发地[联想] 到达地[联想] 日期[date] 票价类型[分段] 目标价[number] [添加任务]`
校验失败在对应字段下红字提示（如「出发地无法唯一匹配，候选：杭州HGH / 湖州HZH」）。

**任务卡片网格**（每任务一张卡，2–3 列）：
- 头部：`SZX→HGH` 大号 20px + 日期；右侧启停开关；
- 中部：目标价 `¥500`、最新价 `¥199`（命中时粉色加粗 + 「已命中」徽章）；
- 底部：最近 7 次价格迷你折线（40px 高 SVG，无坐标轴，只曲线+命中点）；最后查询时间；
- 行内操作：「删除」为文本按钮，点击变红「确认删除？」再点执行。

### 5.3 票据管理

两张票据卡（PLUS 专享 / 普通票价），结构一致：

```
┌  PLUS 专享票据 ──────────────── [测试解析] [清除] ┐
│  状态: ● 已配置（app.hnair.com/.../ffl/airLowFareSearch） │
│  [textarea: 粘贴抓包 cURL ...]                      │
│  校验提示：识别到 URL ✓ / Cookie ✓ / hnairSign ✓     │
│  [保存票据]（主按钮）                              │
└──────────────────────────────────────────────────┘
```

- 已配置状态默认**不显示原 cURL**，只显示「已配置」+ URL 域名/路径 + 更新时间；「查看」按钮展开明文（展开 30s 后自动收起）。
- 校验逐项打勾（URL / Cookie / 签名 / 参数），缺项红字说明缺什么，可保存但提示风险。
- 保存成功 Toast：「PLUS 票据已更新，daemon 下一轮生效」。

### 5.4 微信推送（设置页）

- SendKey 列表：每行 `SCT****abcd` 掩码 + 状态（正常/失效）+ 删除；行尾「发送测试消息」。
- 输入区：多行 textarea（每行一个 key），粘贴即保存候选；按钮「保存并验证」→ 自动发一条测试消息并把结果（成功 x/y）以 Toast 展示。
- 新 key 只在保存后生效，保存前不产生任何网络请求。

### 5.5 监控时段（设置页）

- 两个时间选择器（开始 06:00 / 结束 23:59）+「保存」。
- 说明文案一行：「仅在此时段内轮询抓价，时段外 daemon 待机」。

### 5.6 高级设置（设置页，折叠区）

| 项 | 控件 | 说明 |
|---|---|---|
| 代理 | 文本框 | 格式 `http://user:pass@host:port`，空=直连 |
| 签名刷新 | 开关 | 开启后刷新 stime 并重签；遇验签错误自动回退原签名 |
| 高级说明 | 折叠面板 | 一段 100 字以内的风险提示即可，不做教程 |

### 5.7 凭证安全交互

- 全局规则：任何凭证类值（SendKey、cURL、token）**渲染时默认掩码**，明文只在用户显式点击「查看」后出现；
- 复制按钮：一行内「复制」直接复制明文到剪贴板，但屏幕不显示明文副本；
- daemon 日志若打印了敏感头，前端日志视图做正则脱敏（`token=xxx` → `token=***`）。

### 5.8 历史与日志

- 价格历史：分页或限 50 条表格；命中行高亮；每行操作「趋势」展开该航线最近 30 次折线。
- 运行日志：`/history#log` 锚点页，最近 200 行可滚动，自动刷新开关（默认关）；错误行红字。
- 历史与日志放同一 Tab 的两个子分段，避免导航膨胀。

## 六、删除清单（相对现有 Streamlit app.py）

| 删除项 | 现状 | 理由 |
|---|---|---|
| 微信绑定教程长文案 | `st.expander("微信绑定教程（小白版）")` 整段 markdown | 教程放 QUICK_START 文档，控制台不做教学 |
| 票据管理里的长说明 | 票据区上方多行指引 | 收敛为一行短提示 + 占位符 hint |
| 任务序号数字操作 | `st.number_input("选择要操作的任务序号")` | 卡片直接行内启停/删除，不需要序号 |
| 无意义的「刷新日志」按钮 | 每次手动点 | 改为自动刷新开关 + 轮询 |
| 城市候选大段 info | `st.info("出发地候选：...")` 很长 | 收敛为下拉联想里的 8 条候选 |
| 部署/启动相关元素（若有） | Streamlit 默认的部署菜单 | 纯本地工具，无部署诉求 |
| 多余的成功提示文案 | 多处 `st.success` 长句 | 收敛为统一 Toast 短文案 |
| 表格宽度硬编码 | `st.dataframe(width=800)` | 改为响应式布局 |

保留但重新呈现：票据管理（改为票据页）、SendKey（设置页）、监控时段（设置页）、任务增删启停（任务页）、全局启停（顶部+总览）、价格历史/日志（历史 Tab）、代理（高级设置）。

## 七、动效

- 页面切换：内容区 150ms `opacity + translateY(4px)` 淡入，不做左右滑屏。
- 状态变化：监控启停时顶部指示灯 200ms 颜色过渡 + 图标轻微缩放；徽章出现 120ms 淡入。
- 价格命中：新命中卡片 600ms 一次柔和高亮脉冲（背景色闪两下），然后恢复正常——低频、可感知、不打扰。
- 开关：标准 200ms 滑块过渡。
- 原则：所有动效 ≤600ms，默认关闭 `prefers-reduced-motion` 时全部禁用。

## 八、实现备注（给前端）

- 依赖最小化：React 18 + Vite + 原生 CSS variables（不引 UI 框架也可达标；若求快可用 Tailwind 但 token 必须落到本规范变量）。
- 数据流：前端只读/写 daemon 现有的 JSON 文件（config/tasks/runtime_state/price_history/run_log），经轻量 API 服务（FastAPI 或 Node 均 127.0.0.1 绑定）中转；不直接并发写文件（保留文件锁语义）。
- 刷新策略：总览与任务页 15s 轮询，历史页 30s，设置页不轮询；命中/错误变化触发 Toast。
- 凭证脱敏在前端渲染层做，后端 API 返回原文但仅限本机回环。
